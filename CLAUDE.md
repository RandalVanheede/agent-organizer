# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Agent Organizer: a native macOS app (Swift 6 / SwiftUI, no Xcode required) that keeps project **folders** as vertical tabs in a sidebar and, per folder, runs **agents** (Claude Code, OpenCode, a shell, custom presets) as horizontal tabs, each rendered by SwiftTerm. Every agent is a **tmux session on the app's own socket**, so agents survive the app quitting. `PLAN.md` is the design doc and milestone history; keep it in sync when behaviour changes.

## Build / run

No Xcode project — SwiftPM plus a Makefile that assembles the `.app`. No test target exists.

```sh
swift build -c release          # compile only (fastest way to check for errors)
make                            # = make dmg: bundle, then build/Agent Organizer.dmg (the only thing in build/)
make bundle                     # build + assemble .build/app.noindex/Agent Organizer.app + sign
make run                        # bundle, then open the staged app
make install                    # copy to /Applications
make tmux                       # rebuild Resources/bin/tmux from source (scripts/build-tmux.sh)
make icon                       # re-render Resources/AppIcon.iconset (scripts/make-icon.swift)
make identity                   # create/trust the "Agent Organizer Dev" self-signed signing identity
make release VERSION=1.1.0      # scripts/release.sh: dmg + Sparkle signature + GitHub release + appcast.xml (then commit/push appcast.xml)
```

Iteration loop used throughout development: `pkill -f "Agent Organizer.app/Contents/MacOS/AgentOrganizer"; make run`. Killing the app never kills agents (they live in tmux). The `.app` is staged under `.build/app.noindex/` (Spotlight skips `.noindex`) so only `/Applications` shows up in Spotlight — never stage it in `build/`.

Runtime state lives in `~/Library/Application Support/Agent Organizer/`: `state.json` (all persisted data), `tmux.sock`, `hooks.log`, `events/`, `bin/ao-hook`. Deleting `state.json` gives a clean slate without touching tmux sessions.

## Verifying changes without a GUI test harness

There are no automated tests; verification has been done by:
- Driving tmux directly against the app's socket: `tmux -S "$HOME/Library/Application Support/Agent Organizer/tmux.sock" list-sessions` / `list-panes -a -F '#{session_name} #{pane_id} #{pane_current_command}'`. Use the same binary version as the app (bundled `Resources/bin/tmux` is 3.7c, same as Homebrew's) — protocol mismatch otherwise.
- Firing hook events by hand: `printf '{"hook_event_name":"Notification","message":"x"}' | TMUX="<socket>,1,0" TMUX_PANE="%N" sh Resources/ao-hook.sh Notification`, then reading `hooks.log`.
- Read-only accessibility queries via `osascript` (`System Events` → `process "Agent Organizer"`) work for inspecting windows/menus; sending keystrokes/clicks does not (no Accessibility permission) — don't burn time on it.
- Screenshots are not possible (no Screen Recording permission).

## Architecture — the parts that span files

**Process model.** The app never owns a PTY for an agent directly. `TmuxController` (one-shot `tmux -S <socket> -f <bundled conf> …` invocations) creates sessions named `ao_<folder-slug>_<8hex>`, whose default command is the user's login shell (so PATH/nvm/etc. are right), then `send-keys` the tool's launch command. `TerminalCache` holds one SwiftTerm `LocalProcessTerminalView` per agent for the app's lifetime; its child process is `tmux attach-session -t <session>`. Switching tabs only re-parents the cached NSView (`TerminalHostView`); nothing is torn down until the user kills the agent. "Restart" uses `respawn-pane -k` so a resume command is never typed into a still-running tool.

**Which tmux.** `TmuxPaths.resolveTmuxBinary()` prefers the statically linked `Contents/Resources/bin/tmux`, then Homebrew, then the login shell's PATH. The app's socket and `Resources/tmux.conf` are its own; the user's tmux is never touched. Sessions prefixed `__ao_` are internal plumbing and are filtered out of every user-facing list.

**Live status without polling.** `TmuxControlModeClient` keeps one `tmux -C attach` client on the hidden `__ao_control` session and consumes three kinds of notifications, all of which tmux broadcasts server-wide (verified empirically, not documented): `%sessions-changed` (death/creation), `%window-renamed`/`%unlinked-window-renamed` (live tab titles), and a `refresh-client -B` **format subscription** over `#{S:…}` giving every session's `pane_id|pane_pid|pane_current_command|window_activity|pane_title`. Tab titles prefer a non-shell pane's `pane_title` (Claude Code's topic summary) over the window name. `AppState.recomputeStatuses` derives `AgentStatus`: session gone → `exited`; command is a shell → `idle`; flagged `needsInput` → `waiting` ("needs you"); live sub-agents → `running`; then, for hook-driven agents (hooks reported this run, or the pane runs Claude — a version-string command — while hooks are installed), `running` = between `UserPromptSubmit` and `Stop` (`turnActive`, persisted as `Store.activeTurnSessions` so it survives an app restart; events that arrive while the app is closed are replayed from `events/` on launch) with output in the last 15 s (Esc fires no `Stop`), else `done` — typing or a tab-switch redraw never counts; for hook-less tools, output within 2.5 s → `running`, held until 6 s quiet, else `done`. A 1 s in-memory tick drives the decay; a 10 s `list-sessions` poll is only a safety net and runs off the main thread (`refreshStatuses` → `Task.detached`, newest result wins) — keep periodic tmux calls off the main actor, `TmuxController.run` blocks its caller. `ResourceMonitor` reads CPU/RSS per pane tree via libproc (`proc_listchildpids` + `PROC_PIDTASKINFO`, mach ticks → ns via timebase), using the subscription's `pane_pid`; it never spawns `ps` and pauses while the app is inactive. Claude Code reports its **version string** as `pane_current_command`, so "not a shell" is the tool test — don't match on `claude`.

**Selection model.** `AppState.selectedFolderID` (sidebar) + `activeAgentByFolder` (which tab per folder), both persisted via `Store`. `selectedAgent` falls back to the folder's first agent when the recorded one is gone. `splitAgentID` (side-by-side) only resolves when it points at a live agent in the same folder — stale values render nothing rather than needing cleanup everywhere.

**Folders.** A folder is one sidebar entry regardless of kind: `.repo` (`.git` at root), `.container(repos:)` (sub-repos found to `scanDepth`, default 1), or `.plain`. Sub-repos only feed the "start in…" cwd choice and the branch badges. `FolderScanner` reads `.git/HEAD` directly (follows `gitdir:` for worktrees) — never spawns `git`. `FolderWatcher` puts a `DispatchSource` on each folder root and every known `.git/HEAD` and rescans on change (500 ms debounce).

**New Agent UI.** Presented from a single `.sheet(item:)` in `MainSplitView`, driven by `AppState.newAgentPopoverFolderID`. Do not attach per-row `.popover`s inside `List` section headers — that was the first real bug (mis-anchored, failed to present once a row was selected).

**Look.** Herdr-style flat chrome: sidebar, tab bar and status bar paint `Chrome.background`; the terminal card and `AOTerminalView.applyTheme` use `Chrome.terminalBackground` (grey card on darker chrome in dark mode, white card on grey chrome in light) plus our own fg/caret/selection and 16-colour ANSI palettes (SwiftTerm's default is Terminal.app's, unreadable on grey) — re-applied on appearance change because SwiftTerm bakes colours to fixed values; the window uses `.hiddenTitleBar`, so both columns ignore the top safe area and draw their own 34 pt row beside the traffic lights (sidebar: add-folder menu + `SidebarToggleButton`; detail: the tab bar, which gains the toggle and `FolderSwitcherMenu` while the sidebar is hidden); the terminal sits in an inset bordered card with a header (tool, cwd, status), padded rather than clipped. Folders are grouped under host headers (plain rows, same caret reason as below) only when a remote folder exists.

**Sidebar Folders header** is a plain untagged row inside a headerless `Section`, not a section header: sidebar section headers show a hover collapse caret (`.collapsible(false)` didn't suppress it) that shoved the filter button left. Status tints on sidebar rows (`statusTint`, Colours/Both style) are `listRowBackground`; the native selection highlight intentionally covers them.

**⌘W.** Means Kill Agent (default; rebindable like every shortcut via `ShortcutAction`/`Store.shortcut(_:)`, Preferences › Shortcuts). A local `NSEvent` key-down monitor in `AppDelegate` swallows the Kill Agent combo before menu/window dispatch (ignored while `ShortcutRecorder.isRecording`) and kills the selected agent (no-op with none; Settings window still closes). Don't use an `NSApplication` subclass for this: the SwiftUI lifecycle ignores `NSPrincipalClass` (NSApp is SwiftUI's `AppKitApplication`), which is why the old `AOApplication` approach never worked. ⇧⌘W is an explicit "Close Window" command.

**Claude Code hooks → attention.** `HookInstaller` copies `Resources/ao-hook.sh` to App Support/`bin/ao-hook` and merges `Notification`/`Stop`/`UserPromptSubmit`/`SubagentStart`/`SubagentStop` entries into `~/.claude/settings.json` (other tools' hooks untouched; one-time `.ao-backup`; older partial installs topped up on launch). Live sub-agents keep an agent `running` and swallow its `Stop`. The script no-ops unless `$TMUX` is our socket and writes one JSON file per event to `events/`; `HookEventWatcher` maps `TMUX_PANE` → session (subscription map, `display-message` fallback) → agent. `attention` holds a kind per agent: `Stop` → `.finished` (cleared when the tab is viewed or a prompt is submitted; not flagged while you watch the tab); a `Notification` that means blocked (`notification_type` permission_prompt/elicitation_dialog, see `AppState.notificationKind`) → `.needsInput`, recorded even while watched and cleared only by an answer (output > 3 s after the flag, `UserPromptSubmit`, or the tool exiting). `idle_prompt` (Claude's 60 s "waiting for your input" nudge) only flags `.finished` if nothing is flagged; `auth_success` is ignored. The sidebar's bottom "Agents" panel (`AgentsPanel`) lists agents by status — Needs you / Working / Done — aged from `attention.since` or `AppState.statusSince` (there is no separate "Finished" list: flags kept re-appearing after being clicked away); ⌘J still cycles needs-you then finished. Flags also drive the Dock badge and bounce, ring `Store.attentionSound` via `AppState.playAttentionSound()`, and post a notification. The same sound also fires tool-agnostically (no hook needed) when `recomputeStatuses` sees a `running → done` transition stay quiet for 4 s (flags `.finished`) while the tab isn't on screen — covers OpenCode/custom presets. **System notifications are refused for non-Apple-signed builds** ("Notifications are not allowed for this application" — ad-hoc *and* self-signed alike), so `ToastCenter` shows floating in-app panels instead; the system path is used automatically if ever authorized. Claude Code snapshots hooks at startup: agents running before Install must be restarted. `hooks.log` records every step.

**Remote folders (HBY-13).** `Folder.host` set = remote. Agents stay local tmux sessions whose pane runs `RemoteSession`'s ssh wrapper into a same-named session on the remote's `tmux -L agent-organizer`; no scan/watch/hooks for remote folders, and `recomputeStatuses` never marks them idle (pane is always the `sh` wrapper). Pasting (⌘V/⌃V) in a remote tab with files or an image on the pasteboard uploads them over ssh to the remote's private `~/.cache/agent-organizer-paste/` and pastes the remote paths instead (remote tools can't read the Mac clipboard). URLs opened on the remote (`$BROWSER` / `xdg-open` → `~/.cache/agent-organizer/bin/xdg-open`, installed on every connect) come back as private OSC 7731 (`<token>;<base64 url>`, token = HMAC of the session name with App Support/`opener.key`, passed as `AO_OPENER_TOKEN`), double-wrapped for tmux passthrough; `AOTerminalView` opens http(s) only, and forwards an OAuth `redirect_uri=localhost:<port>` to the remote with `ssh -L` for 10 min. Needs remote tmux ≥ 3.2 (`new-session -e`).

**Stuck server recovery.** A tmux server whose last session died while a client stayed attached refuses every new connection ("server exited unexpectedly"). Seen when an app crash orphaned the `-C attach` control client (reparented to launchd). `TmuxControlModeClient.start` SIGTERMs control clients on `__ao_control` whose parent is pid 1; `TmuxController.recoverIfWedged()` (launch / recheck) pkills every process on our socket when the error shows twice in a row.

**Kill = undoable.** `killAgent` drops the record at once but keeps the session (and cached terminal) for 8 s (`pendingKills`), showing an undo toast; quitting finalizes pending kills. Pending sessions are excluded from orphans. An agent already `exited` is removed immediately. `restartAgent` on an `exited` agent recreates the session under the same name (`startSession`) and discards the dead terminal view; `DetailView` shows a "Session ended" card with Restart / Close Tab over dead panes.

**Updates (Sparkle 2).** `AppUpdater` wraps `SPUStandardUpdaterController`; feed = `appcast.xml` on `main` (raw.githubusercontent), daily checks. Disabled when Info.plist's `SUPublicEDKey` is empty. The EdDSA private key lives only in the maintainer's login Keychain (account `agent-organizer`; `generate_keys --account agent-organizer` / `sign_update --account agent-organizer` from `.build/artifacts/sparkle/Sparkle/bin`). `make bundle` embeds `Sparkle.framework`, adds the `@executable_path/../Frameworks` rpath and stamps `CFBundleShortVersionString` (latest tag or `VERSION=`), `CFBundleVersion` (commit count — what Sparkle compares) and `AOGitCommit`. Updates are code-signature checked too, so releases must be signed with the same "Agent Organizer Dev" identity. About is a custom `Window` (`AboutView`) replacing the stock panel.

**Orphans.** tmux sessions on our socket with no `Agent` record (e.g. after "Remove Folder, Keep Agents Running") are listed as "Unmanaged Sessions" in the sidebar with adopt/kill actions, never silently dropped. `AppState.reconcileSessions` only prunes agents whose session is gone; it never kills a live session.

## Conventions worth knowing

- Persistence is `Store` → `state.json` on every mutation; new fields must be optional in `PersistedState` (or defaulted on load) so existing state files keep decoding.
- `@Observable` + `@MainActor` throughout; delegate callbacks from SwiftTerm/DispatchSource hop to the main actor. SwiftTerm is pinned to `1.20.0` (its `LocalProcessTerminalViewDelegate` is *not* `@MainActor` and has no `processFailedToStart`).
- Sandbox is off and must stay off (arbitrary PATH tools, Unix socket, forkpty).
- Signing: `make bundle` uses the "Agent Organizer Dev" identity when present so the code-signature-tied permissions survive rebuilds; falls back to ad-hoc.
- Commit messages end with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`; commit only when asked.
